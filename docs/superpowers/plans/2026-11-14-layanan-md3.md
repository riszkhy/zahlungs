# Layanan dan Riwayat layanan MD3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/services`, `/services/history` and the Koreksi status popup drawn with the MD3 tokens and `ZahlungsWeb.MdComponents`, behaviour unchanged.

**Architecture:** Four small additions to `MdComponents` (link buttons, textarea, a trailing slot, `md_badge`), then each template rewritten in place: `ServiceCorrection.popup/1` on `md_dialog`, `ServiceLive.Index` in three slices, `ServiceLive.History` last. Events, ids, field names and assigns stay; only markup and classes change.

**Tech Stack:** Phoenix 1.8 / LiveView 1.2 HEEx, Tailwind 3.4 with the `--md-*` roles in `assets/tailwind.config.js`, ExUnit with `render_component/2` and `ZahlungsWeb.LiveDriver`.

**Spec:** `docs/superpowers/specs/2026-11-14-layanan-md3-design.md`

## Global Constraints

- Only presentation: no change to contexts, data, migrations, money rules, events (`phx-click`/`phx-change`/`phx-submit` names and values), element ids or form field names.
- No new dependency (hex or npm), no downloaded font.
- No `.chip`, `.chip-sm`, `.product-tile`, `.btn-primary`, `.form-control`, `.list-card`, `.cart-panel*`, nor Tailwind `gray-*`/`green-*`/`red-*`/`amber-*`/`blue-*` in the templates of `service_live/index.ex`, `service_live/history.ex`, `service_correction.ex`. `.cart-bar` stays (shared CSS), overridden as on the cashier.
- `.header`, `.table`, `.pagination`, `<.modal>`, `<.button>` in `core_components.ex` and `app.css` stay as they are.
- Roots of both pages: `<div class="md3 -m-6 rounded-xl bg-surface p-4 text-on-surface">` (as `cashier_live.ex`).
- Status → badge tone: `success` → `"success"`, `failed` → `"error"`, `processing` → `"warning"`; labels Berhasil / Gagal / Diproses.
- Copy stays as it is today, word for word (Indonesian), except where the spec names a title.
- Run the full suite only with the dev server stopped (`preview_stop`): it deadlocks MySQL otherwise.
- Commits: `type(layanan-md3): subject`, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push or merge.

1. Cara bayar as `md_segmented` without `event`, inside the payment form: picking QRIS must still reach `handle_event("change", ...)` as `service[payment_method]` and hide "Uang diterima" — pinned in Task 4.
