# Riwayat penjualan MD3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/sales` memakai token dan MdComponents MD3, dan Return lewat popup konfirmasi MD3 dua langkah.

**Architecture:** Satu LiveView (`ZahlungsWeb.SalesLive.Index`) ditulis ulang templatenya dengan `MdComponents`; tabel ditulis langsung di halaman; tiga popup `md_dialog`. Return pindah dari event `return` + `data-confirm` ke `prompt_return` → `@returning` → `confirm_return`. Context `Sales` tidak berubah.

**Tech Stack:** Phoenix 1.8, LiveView 1.2 HEEx, Tailwind dengan token `--md-*`, tes ExUnit lewat `ZahlungsWeb.LiveDriver` dan `Phoenix.LiveViewTest.render_component/2`.

**Spec:** `docs/superpowers/specs/2026-11-14-sales-md3-design.md`

## Global Constraints

- Tidak ada perubahan pada context (`Sales`), data, migrasi, aturan uang atau stok.
- Tidak ada dependensi baru.
- Event `filter`, `page`, `prompt_void`, `cancel_void`, `void_change`, `do_void`, id `sale-card-<id>`, `sale-modal`, `void-modal`, field `date` dan `reason` tetap.
- `sale_receipt`, `.pagination`, `.header`/`.table`/`<.modal>` di `core_components.ex` tidak diubah; Kasir tidak berubah.
- Teks status (`completed` / `returned` / `void`) dan label lain tetap seperti sekarang.
- Template `/sales` tidak memakai `.header`, `.table`, `<.modal>`, `<.button>`, `.list-card`, `.form-control`, `btn`/`btn-sm`/`btn-link`, `gray-*`, `green-*`, `red-*`, `amber-*` (kecuali isi `sale_receipt` dan `.pagination`).
- Tes MdComponents tidak bergantung pada urutan atribut (global attrs dirender setelah `class`).
- Commit: `type(sales-md3): subject`, diakhiri `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Return dikonfirmasi dari dua layar yang popupnya sama-sama terbuka → yang kedua dilaporkan "already been returned", stok kembali sekali (tes di Task 2).
2. Klik ganda "Return" → `confirm_return` kedua tidak berbuat apa-apa karena `@returning` sudah nil (tes di Task 2).
3. Kasir mengirim `confirm_return` langsung (tanpa popup, atau `@returning` diisi lewat event palsu) → ditolak, penjualan tetap `completed` (tes di Task 2).
4. Admin "semua toko" (`scope.store == nil`) → kolom Store tampil di tabel dan kartu, Return tetap jalan (tes di Task 3).
5. Penjualan tanpa kasir (`sale.user` nil) atau tanpa item → kartu/tabel tetap render tanpa error (diperiksa di review; tidak ada fixture murah untuk `user` nil).
