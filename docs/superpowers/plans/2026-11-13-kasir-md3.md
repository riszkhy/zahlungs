# Kasir MD3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cashier screen (`/cashier`) in Material Design 3 with the Zahlungs green, on shared MD3 tokens and components that later pages can use.

**Architecture:** MD3 roles as CSS variables (`--md-*`) in `assets/css/app.css`, mapped to Tailwind colours, radii, shadows and type sizes in `assets/tailwind.config.js`. A new `ZahlungsWeb.MdComponents` module of function components (buttons, chips, search, card, segmented, text field, dialog, sheet, icon). The cashier template is rewritten on those components; events, ids, hooks and assigns stay the same. The top bar in the root layout gets the MD3 colours.

**Tech Stack:** Phoenix 1.8, LiveView 1.2, HEEx, Tailwind (JIT) + daisyUI 2.14 (already installed), ExUnit with `render_component/2` and `ZahlungsWeb.LiveDriver`.

**Spec:** `docs/superpowers/specs/2026-11-13-kasir-md3-design.md`

## Global Constraints

- View only: no change to contexts, data, migrations, money rules, events or the cashier flow.
- No new dependency (npm or hex), no downloaded font; `font-family: Roboto, system-ui, sans-serif`.
- Every `phx-*` event, element id and hook (`Beeper`, `BarcodeScanner`, `MoneyInput`, `CurrencyInput`) on `/cashier` stays as it is.
- Text stays as it is (English stays English); only all-caps goes (no `uppercase` on MD3 buttons). Money stays `format_money/1`.
- `<.button>`, `<.modal>`, `<.input>`, `.chip`, `.btn` are not changed; other pages change only through the top bar.
- Touch targets at least 44px.
- Colour values: exactly the hex table in spec §1.
- Light theme only.
- Dev DB holds real customer data: no test data created there without asking; tests use made-up values.

## Review Focus

1. A segmented payment method that isn't allowed for a sale (`sale_method?/1` false) must stay unselectable — the radio `disabled`, no `phx-click`. Test in Task 4.
2. The confirm-sale dialog must still focus Batal first, so a scanner's Enter sells nothing — `Batal` comes before `Ya, selesaikan` inside `#confirm-sale-content`. Test in Task 5.
3. Hooks with `phx-update="ignore"` (`MoneyInput` fields) must keep their ids and attributes after the move into `md_text_field`, or typed amounts are lost on re-render. Test in Task 4 (ids and `phx-hook` present).
4. On a phone the cart sheet must open only on `toggle_cart` and close on its scrim; on wide screens the cart must always be visible. Test in Task 4.
5. An empty cart must keep "Bayar" disabled on the bottom bar. Test in Task 4.
